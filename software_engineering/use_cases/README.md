## How this level fits

User stories say *what* someone wants and *why*; use cases group them into the goals an actor pursues with the system, with a main flow and its alternatives. Sequence diagrams then show *how* one flow runs between classes, and class diagrams show *what* those classes are. Every user story belongs to exactly one use case (checked by the build script: 96 / 96).

- **Status** of a use case is derived from its stories: *Implemented* (all Done), *Partially implemented* (some Done, Partially done or On hold), *Planned* (all To do). Counts: 1 implemented, 6 partially implemented, 17 planned.
- **Phase** spans the sprints of its stories (S0 = P0, S1–S4 = P1, S5–S8 = P2, S9–S12 = P3, S13–S16 = P4). **Priority** is the strongest priority of its stories.
- **Requirements** are the union of the FRs its stories trace to. Steps marked *(planned)* describe intended behaviour of a partially implemented use case.
