## How to read these diagrams

- Participant names are the real classes, functions and ZenML steps of the code ([SD-1](sd1_etl_pipeline_run.md), [SD-2](sd2_medium_extraction.md)), or the planned classes of [`class_diagram.md`](../class_diagrams/README.md) ([SD-3](sd3_trigger_incremental_etl.md) to [SD-8](sd8_account_deletion.md)). Method names match those documents.
- **Implemented** flows ([SD-1](sd1_etl_pipeline_run.md), [SD-2](sd2_medium_extraction.md)) describe the code at the baseline. Where a requirement will change an implemented flow, a `Note` names the requirement (for example "planned FR-ETL-012").
- **Planned** flows ([SD-3](sd3_trigger_incremental_etl.md) to [SD-8](sd8_account_deletion.md)) carry the phase and requirement IDs in their heading. They are the target design and will be revisited at the start of each phase (see [`overall_review.md`](../reviews/overall_review.md)).
- `-)` is an asynchronous message (an event, a scheduled job, a fire-and-forget trigger). `-->>` is a return. `alt`/`opt`/`loop`/`par`/`critical` are UML combined fragments.
- `FR-` is left out of requirement IDs in notes (`ETL-012` means FR-ETL-012).
